See what a Terraform plan opens to the internet.

vpcdiff reads a Terraform plan and shows every path the internet gains or loses, with the security group, network ACL, and route that decides each hop. Free, open source, and offline.

Scan a plan · View on GitHub

How it works

  1. Make the plan: terraform plan -out=tfplan, then terraform show -json tfplan > plan.json.
  2. Run vpcdiff: the GitHub Action on every pull request, the CLI (run it with no arguments for a guided mode that finds or makes the plan), or the offline web viewer.
  3. Read the diff: one verdict for the plan (fix before merge, check by hand, review, or no new exposure), then every path from the internet, its answer before and after the plan, and the hop that changed.
  4. Gate the merge: the Action fails the check when the plan adds a path from the internet.

What it checks

Public IP, internet gateway, network ACL inbound, security groups, network ACL outbound (ephemeral ports), and the return route, for aws_instance, aws_db_instance, and aws_lb. Anything it cannot decide is reported as unknown with the reason.

Questions

Does vpcdiff need AWS credentials or an AWS account?
No. It reads the JSON that terraform show produces. Terraform needs credentials to make the plan; vpcdiff does not.
Does my plan leave my machine?
No. The CLI and the GitHub Action run where you run them. The viewer analyzes the file in your browser tab, and its Content Security Policy blocks every data request. The Action writes a comment to your own pull request only when you turn that on.
What does unknown mean?
The engine could not decide that hop: a value Terraform learns only at apply time, a resource it does not model yet, or a load balancer whose subnets give different answers. The reason is always shown. Unknown is a result, never a guess.
How is this different from Checkov, tfsec, or Trivy?
Those tools judge each rule on its own. vpcdiff follows the whole path: an open security group behind a network ACL that denies the port is not an exposure, and a narrow rule can still open a path when a route changes.
How is it different from AWS Reachability Analyzer?
Reachability Analyzer checks a live account, one path at a time, after you deploy. vpcdiff works on the plan, before you apply, for every endpoint at once. Each test fixture includes the steps to check it against Reachability Analyzer; those paid checks have not been run yet.
Does it check traffic between my own services?
Not yet. Today it checks paths from the internet to instances, databases, and load balancers. Paths inside the VPC are next on the roadmap.
Can it block a pull request?
Yes. The GitHub Action fails the check when the plan adds a path from the internet (you choose the level with fail-on), writes the report to the job summary, and keeps one comment on the pull request up to date.
What does it cost?
Nothing. vpcdiff is free and open source under the Apache 2.0 license.
